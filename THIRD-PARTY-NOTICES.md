This file is generated by `scripts/third_party_notices.py` from the
vendored trees and from `cargo metadata`, not written by hand.
Regenerate it after any version bump; `--check` fails the build when it
is stale. The receipt at the end records the digests it was derived
from.

An installed application carries it, and the two licences it refers
to, at the application root, put there by
`desktop/tauri/tauri.conf.json`:

    %LOCALAPPDATA%\Programs\Hearth\LICENSE.hearth.txt
    %LOCALAPPDATA%\Programs\Hearth\NOTICE.txt
    %LOCALAPPDATA%\Programs\Hearth\THIRD-PARTY-NOTICES.md

and again inside `%LOCALAPPDATA%\Programs\Hearth\hearth\`, where
`scripts/build_windows.py` stages them next to the code they describe,
together with `vendor\licenses\`. Tauri puts resources beside the
executable rather than under a `resources\` directory, so none of
those paths has `resources\` in it.

## Copyleft, and what it obliges

Nothing in the installer is GPL, LGPL, AGPL or SSPL. The generator
splits every crate's SPDX expression into identifiers and fails the run
outright if one of those four appears, so a dependency bump that pulls
in a GNU-licensed crate stops the build rather than shipping. That
check is exact rather than a search for a phrasing: cargo states every
crate's licence in machine-readable form, so there is nothing to miss.

Something genuinely different is present, though, and it is worth
being exact about. There are 5 crates under MPL-2.0:

The Mozilla Public License 2.0 is weak copyleft at file granularity.
It reaches the files that are already under it and nothing else:
section 3.3 says outright that a Larger Work may be distributed under
other terms, so Hearth's own Apache-2.0 code and the other crates in
the executable are unaffected. What it does oblige when a binary is
handed to someone, and how each obligation is met:

1. **Tell recipients how to get the Source Code Form, and let them have it.**
   Section 3.2(a), at no more than the cost of distribution.
   Hearth links these crates exactly as published, with no
   patches, so the Source Code Form is the published crate itself and
   naming the exact version is what makes it obtainable. crates.io
   serves the archive for a name and a version indefinitely, and a
   version that is yanked stays downloadable:

   - <https://crates.io/api/v1/crates/cssparser/0.36.0/download>
   - <https://crates.io/api/v1/crates/cssparser-macros/0.6.1/download>
   - <https://crates.io/api/v1/crates/dtoa-short/0.3.5/download>
   - <https://crates.io/api/v1/crates/option-ext/0.2.0/download>
   - <https://crates.io/api/v1/crates/selectors/0.36.1/download>

2. **Do not use the executable's own licence to cut those rights down.**
   Section 3.2(b). Hearth's Apache-2.0 grant covers Hearth's code. It
   says nothing about these files and takes nothing away from anyone's
   rights in them.
3. **Leave the notices in the covered source alone.** Section 3.4. The
   crates are linked as published and nothing is modified, so there are
   no Modifications and no altered notices. `selectors` is the one that
   ships no LICENSE file of its own; its MPL header is in its source
   files, which is what section 3.4 is about.

Section 3.2 does not literally require the licence text to travel with
an executable, the way section 3.1 does for source. It ships anyway:
`vendor/licenses/licence-MPL-2.0.txt` is inside the application and is
reproduced at the end of this file, because a recipient who has to go
looking for the terms has been given the letter of the licence and not
the point of it.

Two things this rests on that are worth stating rather than assuming.
If Hearth ever vendors a patched copy of one of these crates, the
patched files are Modifications, they have to be published under
MPL-2.0, and this section has to say where; nothing in the build does
that today, and the checksums cargo verifies against `Cargo.lock` are
what make that checkable rather than a promise. And the source links
above depend on crates.io continuing to serve those archives. If that
ever stops, the obligation falls back on Hearth: anyone entitled to the
Source Code Form may ask through the contact route in `SECURITY.md` and
will be given it.
