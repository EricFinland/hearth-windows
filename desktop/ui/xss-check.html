Untrusted content check

Feeds hostile payloads through every rendering path the UI uses for model output, tool output, file content, and tool arguments, then inspects the resulting DOM. A pass means the payload exists in the page only as literal text: no element it named was created, no event-handler attribute survived, and no side effect fired.

The second half of the page asks a different question: not whether text can become structure, but whether the text on screen is the text that is there. A U+202E in a tool argument reorders the glyphs without touching a byte of what runs, which turns the approval card into the attack. Those rows measure each character's on-screen x coordinate and compare the resulting left-to-right reading order against the string itself, because textContent cannot answer that question. Right-to-left languages are checked in the same way and must still read right to left: the fix removes the explicit override controls, not the bidi algorithm.
